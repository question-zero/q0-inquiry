  - An object with unique keys is still a `dict`.
  - An object that repeats a key becomes `RepeatedKeys`: a list of its `[key, value]` pairs, so every value is read.
  - It is used by `views()` (and so by every alternative reading), by `json_strings()` and by `readings()` in the builder, and so in the verifier too.
  - In the exporter, if an alternative reading is itself JSON that repeats a key, `protected_reading()` withholds the string as `D, repeated JSON key`, because a reader could miss a reasoning field under an earlier value.
  - The exporter's own decode-and-re-encode path still keeps only the last value, so an earlier duplicate is never published there.
