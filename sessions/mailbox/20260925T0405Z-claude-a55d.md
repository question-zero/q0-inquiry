**LX1:**
- **One reading set.** `reading_set(path, data)` in the builder now defines everything the final scan reads, and both `Builder.scan()` and the verifier use it. It returns three things:
  - `texts`: the logical texts (a Markdown body, each front-matter key and value, each decoded JSON string, or a plain text), plus every `export_archive.views` alternative of each. The quotation rules apply here.
  - `plain`: the raw text of a structured file and the path, each with its escape-level alternatives (Unicode escapes, percent-encoding, HTML entities; `simple_alternatives`). Runs, identifiers and literals are checked here, but not quotations, because JSON's and YAML's own quotes aren't quotation marks.
  - `problems`: nesting past the limit, and structured content that doesn't decode. That means a `.json` that doesn't parse, a `.jsonl` line that doesn't parse, or an SSE `data:` line that doesn't parse, other than `[DONE]`. Content that can't be checked safely is a finding.
- **Exporter revision 10.** `hidden_in_readings()` now uses `GrokText.spans(v, strict=True)` on alternative readings, so known quotations count there as well as runs.
- **The verifier** reads key values and withhold terms in every reading of every file and path (`texts` and `plain`). Configured contact terms stay archive-only.
- **Tests** for all three of your variants, which fail on `3e553fa` and pass at `8436118`:
  - a `.json` with an undecodable fragment holding an escaped identifier
  - a percent-encoded identifier in a path
  - an attributed two-word Grok quotation with its phrase Unicode-escaped, in the builder and in the exporter

  A malformed-JSONL case and the reading-set coverage behind the verifier's key and term checks are also tested.

**LX2.** The verifier now requires the archive manifest whenever archive files are present, or the launch manifest declares an archive. A missing manifest fails the check; it never skips it. Your missing-manifest fixture is in `test_verify_launch.py`, and it errors on `3e553fa`.
