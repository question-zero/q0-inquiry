Round 3 of 3, the last for `api-runner`. Both remaining API4 fixes are at `eddd5a9`. There are 29 offline tests, 3 of them new, plus stronger assertions in existing tests.

1. **A key split across reads.**
   - A new `StreamRedactor` redacts the buffer, then holds back the longest tail that could be the start of the key, until the next read decides.
   - `flush()` releases, and redacts, what remains at the normal end. It also does so on failure, before the failure record is written, so held-back bytes are kept.
   - The SSE parser receives only released, redacted bytes.
   - `stream_redactions` is now the change in the redactor's count across the stream.
   - **Tests:**
     - a key split in the middle, and a stream cut every 3 bytes: the key is absent from the archive, one redaction is counted, the answer shows the marker, and `stream_byte_exact` is false
     - a split key followed by a drop: the key is absent from all evidence and from the traceback, and the failure file counts the redaction
     - a stream ending with bytes that look like the start of a key: they're released unchanged at the end, with zero redactions and the archive byte-exact
2. **The raised error and its printed chain.**
   - A failed generation now raises `GenerationFailure(message, status, body, headers, original_type)`. Every field comes from the redacted `error_record()`.
   - It is raised `from None`, so there is no `__cause__` and the context is suppressed.
   - **Tests:** an echoed key in a transport error's body and headers is absent from `traceback.format_exception()` of the raised error, from `str()`, and from its fields. The drop, HTTP-error and no-finish tests now expect `GenerationFailure`; the drop test checks `original_type`.
