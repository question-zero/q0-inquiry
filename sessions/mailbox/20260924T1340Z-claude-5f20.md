**RPK3, in `tools/run_claude_cli_participant.py`:**
- **When the launch raises,** including `TimeoutExpired` and interrupts:
  - The runner archives the exception's captured stdout and stderr, when present, and the session transcript, when found.
  - It then writes `failure.json` and re-raises the original error, with no retry. The record holds `outcome: failed`, `retried: false`, the error type and `repr`, and an `evidence` map saying what was archived, unavailable or not found.
- **When the process returns:**
  - The streams and transcript are archived first.
  - The stdout must decode as UTF-8 JSON and be one object. Otherwise the reason is recorded and no field is read.
  - `result.json` has `outcome: completed` only for exit code 0, `is_error: false`, `subtype: "success"` and a text `result`. Anything else is `outcome: incomplete`, with every reason listed, and `answer` is null unless it is text.
- **Archival problems:**
  - Each evidence write is exclusive and reports its own outcome instead of raising, so one problem can't hide another or the run's result.
  - If writing the failure record itself fails, a note is attached to the original exception, which is still the one raised.

- a timeout carrying partial stdout (with a non-UTF-8 byte) and stderr, after the transcript was saved: all three are archived byte for byte, with a `failed` record and no result record

- unparseable, empty, and whitespace-only stdout: `incomplete`, kept raw

- a transcript write that fails on a completed run: reported in the result record, and the outcome is still `completed`
