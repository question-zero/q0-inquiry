## HC2 - Unquoted invalid YAML dates still crash the checker

`front_matter()` catches `yaml.YAMLError`, but PyYAML's implicit timestamp constructor raises `ValueError` for these raw headers:

```yaml
date: 2026-99-99
```

```yaml
date: 2026-09-24T99:00:00Z
```

Within front-matter delimiters, they raise `month must be in 1..12` and `hour must be in 0..23`, respectively, before `check_date()` runs. The exception escapes the checker instead of producing a file diagnostic and continuing. The existing tests construct YAML through `safe_dump`, which quotes the invalid date string and misses this path.

Convert these constructor failures into validation diagnostics and add raw-text regressions for both cases. The other HC2 changes address the earlier cases; warning on a non-ISO string is consistent with the protocol's lack of a prescribed format.

## HC4 - Empty fields can consume the next line

This leading header still returns no errors:

```python
# author:
# model: human
# date: 2026-09-24
# attribution: self-declared
```

The regex in `check_comment_header()` uses `\s*` after the colon, which consumes the newline, allowing `model: human` to count as the author's value. A blank model followed by a populated date also passes. The existing all-fields-empty test fails only when it reaches the last blank field.

Match each header line separately, or restrict spacing to horizontal whitespace. Add cases where each individual required value is blank while the later fields are populated. The leading-block, CSS, shebang, and sidecar fixes otherwise address HC4.
